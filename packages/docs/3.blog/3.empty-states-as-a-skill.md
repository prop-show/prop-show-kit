# Empty states as a skill, not a folder of drawings

> One prompt from X became fourteen illustrations, a generator, a test, and an agent
> skill that keeps the set honest as components are added.

Every registry component needs a picture for the moment it has nothing to show: an
empty bookmarks folder, a filter that matched nothing, a team with nobody in it. Those
pictures are easy to draw once and hard to keep consistent across thirteen components in
two themes.

This post is about the small system we ended up with, and it publishes both the prompt
it started from and the skill that reproduces it.

## It started with one prompt

The art direction came from a prompt for a browser-extension empty state, shared by
[@Kubai087](https://x.com/Kubai087/status/2113849121299894727). Its rules are the
reason the set looks like a set instead of thirteen illustrations by thirteen hands.

The 【bracketed slot】 is the only part that changes per component. Everything else —
canvas, plate, surfaces, placeholder type, icons, the single accent rule, dark mode,
composition and the technical constraints — carry over verbatim, and that is what makes
thirteen different screens look like one set.

```text
画一张浏览器扩展的空状态插图，场景是【书签文件夹里什么都没有】。风格是“缩小版的真实产品界面”，不是插画。输出一个独立的 inline SVG。

画布与底板
- viewBox 0 0 160 120，圆角 18 的底板铺满画布。
- 底板浅色 #fafafa；上面叠 45° 细斜纹，线宽 1，间距 7，颜色 rgba(15,23,42,0.05)；内描边 1px rgba(15,23,42,0.07)。

物体（缩小版的真实产品界面）
- 白色不透明卡片或窗口，圆角 10–13；1px 描边 rgba(47,42,34,0.08)；阴影向下偏移 5、模糊 4.5、颜色 rgb(47,42,34)、不透明度 0.13。
- 浏览器窗口顶部是 18 高的标签条 #eef1f5，激活的标签是白色，圆角 5。
- 文字一律用占位条代替：普通 4 高 #e5e9ef，标题 5 高 #cdd4de，两端全圆角。
- 空格子 #f1f3f6；露在后面的卡片 #f3f3f4。
- 图标只用 Remix icon的线性款。普通图标 #a3abb7，次要操作 #6b7280。
- 只有一个强调色元素，表示下一步操作（按钮、重试、新增）；没有下一步就不用强调色。强调色 #3462ad。按键或主按钮用石板灰渐变 #404859 → #273042，上面配白色图标。

深色模式
- 底板 #26262b，斜纹 rgba(255,255,255,0.035)，表面 #323238，标签条 #2a2a2f，占位条 #3f3f47 / #52525b，图标 #7d828c，强调色 #7ea6ea，阴影黑色、不透明度 0.36。
- 颜色写成 CSS 变量，放在 SVG 内部的 <style> 里，并用 SVG 自己的 id 限定作用域。根元素写 data-theme="light|dark|auto"；auto 跟随 prefers-color-scheme。

构图
- 画的是这个空状态在真实界面里的样子，按比例简化；不要抽象符号。
- 一个场景，2–3 个物体，外接框居中于 (80, 60)，四周留白至少 14。
- 不要文字、人物、渐变插画背景，也不要半透明物体互相叠加。

技术
- 不引用外部资源，不用 <image> 或 <use>。
- 阴影用 feGaussianBlur + feOffset + feFlood + feComposite + feMerge 拼出来，不要用 feDropShadow（有些 HTML 解析器会把它的名字转成小写）。
- 所有 id 都带上同一个随机前缀，同一页放多张图也不会冲突。
- 可选动画：强调色元素在 prefers-reduced-motion: no-preference 时做一次缩放弹出，用 transform-box: fill-box。
```

## Why a “miniature real UI” and not an illustration

The first attempt at `/components` embedded the real components as thumbnails. That
looked right until we measured it:

| List page                               | Real component previews                        | SVG thumbnails             |
| :-------------------------------------- | :--------------------------------------------- | :------------------------- |
| Frame / Layer Dialog card               | just an `Open framed dialog` button            | the window itself          |
| First paint                             | 13 empty divs, everything mounts on the client | 10 SVGs inline in the HTML |
| Interactive controls inside a card link | 8 of 8 cards affected, one `<a>` in `<a>`      | none                       |
| Page height                             | 13 screens                                     | 3–4 screens                |

A dialog is invisible until you open it, and a copy button is a button. The picture has
to show the shape of the screen, so the empty state is drawn as a _reduced product
screenshot_: a plate, a window, placeholder bars where the text goes, one accent element
marking the next step.

## What is in the folder

```
artifacts/illustrations/
  prompt.md       art direction (the X prompt, extended with dark mode rules)
  SKILL.md        the agent skill: how to add the next one
  generate.mjs    scene templates + the shared plate/shadow/theme contract
  icons.json      Remix *-line path data, so no SVG loads anything external
  check.mjs       spec + registry coverage assertions
  index.html      light / dark / auto gallery
  svg/*.svg       the output — never edited by hand
  README.md       per-component summary and the scene each one got
```

`generate.mjs` owns everything that must never drift: the 18-radius plate with its 45°
stripes, the `feFlood → feComposite → feGaussianBlur → feOffset → feMerge` shadow, the
scoped CSS variable block for light, dark and `prefers-color-scheme: auto`, and the
optional pop/ping animations. A scene is only `{ aria, back(), surface(), content() }`,
composed from helpers like `BACK`, `PAGE`, `WINDOW`, `title`, `line`, `icon`, `slate`.

Every illustration is a standalone 160×120 SVG with its own id prefix (`es06cop`) and a
`<style>` block scoped to it, so any number of them can share a page. All fourteen
together are 9 KB gzipped. No external resource, no `<image>`, no `<use>`, no
`feDropShadow`.

## The check is part of the design

`check.mjs` fails the build-quality gate in two directions:

```
no illustration for registry item "filters" — add a scene in generate.mjs
illustration "filters" has no registry item (or remove it from generate.mjs)
```

Adding a component without an illustration is now a failing check instead of a
forgotten drawing. The check covers `registry:component` items. Marketing blocks
(`registry:block`) are full screens, not empty states, so they are outside that
inventory; a scene that does not match any registry item still fails, except
`bookmarks-empty`. It also asserts the visual contract: every id carries the file's
prefix, every object sits inside the 14px safe area, no forbidden construct appears, and
the required shadow primitives are present.

## The skill

The workflow is published as an agent skill that ships with this repository —
[`artifacts/illustrations/SKILL.md`](https://github.com/prop-show/prop-show-kit/blob/main/artifacts/illustrations/SKILL.md).
It is plain Markdown with frontmatter, so any agent that reads skills can follow it:

```md
---
name: generate-empty-state-svg-illustrations
description: Add or update the 160×120 empty-state SVG preview for a show.prop.kit ...
---

## When to use

## Procedure ← 8 steps, from reading the component to committing the SVG

## Pitfalls ← rsvg-convert paints the plate black; one accent per scene; ...

## Verification ← check.mjs, headless Chrome, vp check
```

The pitfalls are the expensive part, and they were all learned the hard way:

- Do not preview with `rsvg-convert` or `qlmanage` — they ignore the SVG's own CSS
  variables and paint the plate black. Use headless Chrome.
- A leftover template token in a class or `url(#…)` silently breaks a filter.
- Keep `index.html` a checked-in file; if the generator writes HTML, `vp check`
  reformats it and the next run reintroduces the diff.
- Exactly one accent element per scene. Toggles, status dots and key chips use grey or
  the slate gradient, otherwise the "next step" signal is lost.

## Adding the next component

```sh
# 1. add a scene to scenes in artifacts/illustrations/generate.mjs
# 2. generate just that one, then verify the whole set
node artifacts/illustrations/generate.mjs <name>
node artifacts/illustrations/check.mjs

# 3. look at it, in both themes
python3 -m http.server --directory artifacts/illustrations
```

Fourteen illustrations cover the thirteen registry items and the bookmarks scene the
prompt started from. Components not yet in the registry have no picture yet, and
`check.mjs` will say so the moment one is added.
