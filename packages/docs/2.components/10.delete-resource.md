# Delete Resource

> A deletion dialog that requires the resource name to confirm, inspired by [Kumo Delete Resource](https://kumo-ui.com/blocks/delete-resource/).

::delete-resource-preview
::

## Install

:registry-install{url="/r/delete-resource.json"}

## Usage

```vue
<script setup lang="ts">
import { ref } from "vue";
import { DeleteResource } from "@/components/delete-resource";
import { Button } from "@/components/ui/button";

const open = ref(false);
const isDeleting = ref(false);
const errorMessage = ref("");

async function handleDelete() {
  isDeleting.value = true;
  errorMessage.value = "";
  try {
    // Replace this request with your resource deletion API.
    const response = await fetch("/api/zones/example.com", { method: "DELETE" });
    if (!response.ok) throw new Error("Unable to delete this zone.");
    open.value = false;
  } catch {
    errorMessage.value = "Unable to delete this zone. Please try again.";
  } finally {
    isDeleting.value = false;
  }
}
</script>

<template>
  <DeleteResource
    v-model:open="open"
    resource-type="Zone"
    resource-name="example.com"
    :is-deleting="isDeleting"
    :error-message="errorMessage"
    @delete="handleDelete"
    @update:open="errorMessage = ''"
  >
    <template #trigger><Button variant="destructive">Delete Zone</Button></template>
  </DeleteResource>
</template>
```

The parent owns the request, loading and error state. Set `isDeleting` before awaiting the request and close the dialog only after success. The component never deletes data itself.

The resource name in the confirmation prompt is rendered with [Inline Copy Text](/components/inline-copy-text), so clicking it copies the exact value to the clipboard instead of forcing users to retype it.

## Error state

::delete-resource-preview{variant="error"}
::

Failed requests keep the dialog open and preserve confirmation for retry. Opening or closing the dialog, or changing the resource name/type, clears the input. Matching preserves whitespace and is case-sensitive by default. Empty resource names cannot be confirmed.

## Props

| Name               | Type                      | Default                 | Description                                   |
| :----------------- | :------------------------ | :---------------------- | :-------------------------------------------- |
| `open`             | `boolean`                 | `false`                 | Open state via `v-model:open`                 |
| `resourceType`     | `string`                  | Required                | Resource type used in the heading and action  |
| `resourceName`     | `string`                  | Required                | Exact name to type                            |
| `isDeleting`       | `boolean`                 | `false`                 | Disables input, submission and user dismissal |
| `caseSensitive`    | `boolean`                 | `true`                  | Whether name matching respects case           |
| `deleteButtonText` | `string`                  | `Delete {resourceType}` | Idle action label                             |
| `errorMessage`     | `string`                  | —                       | Error announced with `role="alert"`           |
| `class`            | `HTMLAttributes['class']` | —                       | Dialog content classes                        |

## Events and slots

- `delete`: emitted on a valid submission; handle the asynchronous operation in the parent.
- `update:open`: emitted when the user opens or closes the dialog.
- `trigger`: optional trigger button. You can also control `open` externally.
- `description`: replaces the permanent deletion warning for your resource.

Escape and Cancel dismiss the idle dialog. Clicking outside never dismisses it. Focus is trapped while open and returns to the slotted trigger on close.
