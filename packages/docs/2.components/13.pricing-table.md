# Pricing Table

> Compare pricing tiers and grouped features in a responsive table that becomes tier cards on mobile.

## Install

:registry-install{url="/r/pricing-table.json"}

## Usage

Pass ordered `tiers` and `sections` to compare plans. Team is highlighted; each CTA updates the selection message. When the component has less than 640px of available width, the same data and slots render as cards. This also works inside narrow documentation columns and side panels.

::pricing-table-preview
::

:example-source{path="PricingTablePreview.vue"}

## Tiers

Use `tiers` on its own for plan headers without feature sections. Each tier needs a unique `id`; optional fields include title, description, price, badge, billing terms, button and highlight.

::pricing-table-tiers-preview
::

:example-source{path="PricingTableTiersPreview.vue"}

Import `PricingTableTier` and `PricingTableSection` from `@/components/pricing-table`. Narrow tier IDs to a literal union so `PricingTableSection<Tier>` checks feature keys and scoped slots preserve additional tier fields. Tier order controls columns and mobile cards; feature maps use IDs, not positions.

## Sections

Group features with `sections`. Each group has a title and features; each feature maps tier IDs to values. Use unique, stable section IDs and feature IDs, with feature IDs unique across sections because slot names are shared.

::pricing-table-sections-preview
::

:example-source{path="PricingTableSectionsPreview.vue"}

| Value                          | Default rendering                                 |
| :----------------------------- | :------------------------------------------------ |
| `true`                         | Check icon with screen-reader text “Included”     |
| `false`                        | Minus icon with screen-reader text “Not included” |
| Number, including `0`          | Number as text                                    |
| String                         | String as text                                    |
| Missing tier key (`undefined`) | Em dash (`—`)                                     |

`PricingTableFeatureValue` is `string \| number \| boolean`. Feature maps are partial; omit a key for unspecified values. Values are not automatically formatted or localized, and `null` is outside the type contract.

## Discounts

Set `price` to the original amount and `discount` to the current amount. `billingCycle` labels the unit price and `billingPeriod` adds billing context. This example combines monthly billing, an annual seat price and custom pricing to show header alignment with different content.

## Slots

Override individual parts with scoped slots. This example adds a crown to Team, a shield to Security and badges to developer counts.

::pricing-table-slots-preview
::

:example-source{path="PricingTableSlotsPreview.vue"}

| Slot                                  | Payload                                                                       | Purpose                                                                                       |
| :------------------------------------ | :---------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------- |
| `caption`                             | None                                                                          | Desktop screen-reader caption                                                                 |
| `tier`, `{tierId}`                    | `{ tier: T }`                                                                 | Complete tier header                                                                          |
| `tier-{name}`, `{tierId}-{name}`      | `{ tier: T }`                                                                 | Header part; names: `title`, `description`, `badge`, `button`, `billing`, `discount`, `price` |
| `section-title`, `section-{id}-title` | `{ section: PricingTableSection<T> }`                                         | Section heading                                                                               |
| `feature-title`, `feature-{id}-title` | `{ section, feature: PricingTableSectionFeature<T> }`                         | Feature label                                                                                 |
| `feature-value`, `feature-{id}-value` | `{ section, feature, tier: T, value: PricingTableFeatureValue \| undefined }` | Feature cell for a tier                                                                       |

ID-specific slots take precedence over shared slots, even when empty. For example, `team-title` overrides `tier-title` for Team. The direct `team` slot overrides `tier` and replaces the entire header, including price, badge and button; smaller tier slots do not apply inside that replacement.

`tier-discount` replaces the original price's struck-through text; supplying that slot also creates the discount element without a `discount` prop. `tier-price`, `tier-billing` and `tier-button` can likewise render without corresponding tier data.

Without an explicit section or feature `id`, the slot ID comes from its title: lowercase, trimmed, with runs of non-letter/non-number characters replaced by a hyphen and leading/trailing hyphens removed. “Guest seats” becomes `guest-seats`. Explicit IDs keep slots stable when labels change or are translated.

A shared `feature-value` slot replaces every built-in value renderer. Handle booleans with equivalent accessible text and use `value ?? '—'` for other values so zero remains visible.

Slots render in both responsive layouts. Avoid fixed DOM IDs and effects that assume one instance. The desktop uses a semantic table with column, feature and section headers; mobile uses labeled articles and definition lists. The inactive layout is hidden with CSS. A custom `caption` slot changes only the desktop caption; keep a meaningful `caption` prop for the mobile group's label.

## API

| Name       | Type                                     | Default                     | Description                                   |
| :--------- | :--------------------------------------- | :-------------------------- | :-------------------------------------------- |
| `tiers`    | `T[]` where `T extends PricingTableTier` | Required                    | Ordered tiers, each with a unique string `id` |
| `sections` | `PricingTableSection<T>[]`               | `[]`                        | Ordered feature groups                        |
| `as`       | `string \| Component`                    | `'div'`                     | Outer wrapper, not the table element          |
| `caption`  | `string`                                 | `'Pricing plan comparison'` | Desktop caption and mobile group label        |
| `class`    | `HTMLAttributes['class']`                | —                           | Wrapper classes                               |

`PricingTableTier` requires `id: string` and accepts optional `title`, `description`, `badge`, `billingCycle`, `billingPeriod`, `price`, `discount`, `button` and `highlight` from Pricing Plan. It does not expose card features, variant, scale or orientation. `button` uses `PricingPlanButton`, including `onClick` for application actions and `href` for links.

`PricingTableSection<T>` contains optional `id`, required `title` and a `features` array. Each `PricingTableSectionFeature<T>` has optional `id`, required `title` and `tiers: Partial<Record<T['id'], PricingTableFeatureValue>>`.

The index exports `PricingTable` and these types:

- `PricingTableTier`, `PricingTableFeatureValue`, `PricingTableSectionFeature<T>`, `PricingTableSection<T>` and `PricingTableProps<T>`.
- `PricingTableTierSlot`, `PricingTableTierSlotProps<T>`, `PricingTableSectionSlotProps<T>`, `PricingTableFeatureSlotProps<T>`, `PricingTableFeatureValueSlotProps<T>` and `PricingTableSlots<T>`.

The generic types default to `PricingTableTier` when omitted. No component-specific events are emitted; use each tier's `button.onClick` or a custom button slot and keep selection state in the parent.
