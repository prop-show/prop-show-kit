# Workspace

> 工作台 screens for an app: a project overview, a team directory, and workspace settings.

These three blocks are product screens rather than marketing sections. Each one composes kit components — Frame, Status Badge, Layer Dialog — with shadcn-vue primitives. Install one when you want the screen, not when you only need a single control. The single controls live under [Components](/components).

The previews keep their data in memory. Invitations do not send email, and saved settings return to the sample values on refresh. Treat the files as the place where your own requests and persistence plug in.

- [Project Overview](/blocks/project-overview) — metric cards, deployment status, and a switchable reporting period. Narrow the preview to see the cards stack.
- [Team Members](/blocks/team-members) — search, member status, an empty state, and an invitation dialog that rejects a duplicate email. The code tab shows the member list and the dialog as separate files.
- [Workspace Settings](/blocks/workspace-settings) — an editable form, notification preferences, unsaved-change feedback, and save and discard actions.

```bash
npx shadcn-vue@latest add https://kit.prop.show/r/project-overview.json
```

The same command works for `team-members` and `workspace-settings`. Registering `@propshow` lets you write `@propshow/project-overview` instead of the URL. See [The @propshow registry](/guide/registry).
