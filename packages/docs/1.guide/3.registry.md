# The @propshow registry

> PropShow Kit is published as a shadcn-vue registry named `@propshow`. There is no npm package to install.

Every component and every block is a JSON document under `https://kit.prop.show/r/`. The `shadcn-vue` CLI reads that document and writes the source files into your repository, along with the dependencies the entry declares. After that write, the files are yours: they are not updated by a package version.

The index of every entry is [`https://kit.prop.show/r/registry.json`](https://kit.prop.show/r/registry.json). Individual entries are `https://kit.prop.show/r/{name}.json` — for example [`frame.json`](https://kit.prop.show/r/frame.json) and [`project-overview.json`](https://kit.prop.show/r/project-overview.json).

## Install with a URL

This works as soon as the project has been set up for [shadcn-vue](https://www.shadcn-vue.com/docs/installation.html). You do not need to register a name first.

```bash
npx shadcn-vue@latest add https://kit.prop.show/r/frame.json
```

Pass several URLs to install several entries in one command:

```bash
npx shadcn-vue@latest add https://kit.prop.show/r/frame.json https://kit.prop.show/r/project-overview.json
```

The URL is the same one shown on each docs page, and the one copied from the homepage.

## Register the @propshow alias

To install by name, add the registry to the `registries` field of `components.json`:

```json
{
  "registries": {
    "@propshow": "https://kit.prop.show/r/{name}.json"
  }
}
```

`{name}` is a placeholder the CLI replaces. It is not something you edit per component.

```bash
npx shadcn-vue@latest add @propshow/frame
npx shadcn-vue@latest add @propshow/pricing-plan
npx shadcn-vue@latest add @propshow/workspace-settings
```

`@propshow/frame` and the `frame.json` URL install the same entry. The alias is a shortcut for that URL. If `components.json` has no `@propshow` key, the CLI does not know the name — use the URL until the key is there.

## What the CLI writes

An entry can declare two kinds of dependencies:

- **shadcn-vue primitives**, by their official names: `button`, `input`, `tooltip`, `badge`, `dropdown-menu`, `avatar`, and others. The CLI fetches those from the official registry. PropShow Kit does not republish them.
- **Other PropShow entries**, by URL. A workspace block, for example, pulls in `frame`.

npm packages such as `@lucide/vue` and `@vueuse/core` are declared the same way and installed with your package manager.

Components usually land in one directory, such as `@/components/frame/`. Blocks often land as several files under their own directory, such as `@/components/team-members/`.

## Names

The name in `@propshow/{name}` matches the file name in `/r/{name}.json` and the last segment of the docs URL.

| You want           | Docs                                                     | Install name         |
| ------------------ | -------------------------------------------------------- | -------------------- |
| Frame component    | [/components/frame](/components/frame)                   | `frame`              |
| Password input     | [/components/password-input](/components/password-input) | `password-input`     |
| Phone input        | [/components/phone-input](/components/phone-input)       | `phone-input`        |
| Pricing table      | [/components/pricing-table](/components/pricing-table)   | `pricing-table`      |
| Project overview   | [/blocks/project-overview](/blocks/project-overview)     | `project-overview`   |
| Workspace settings | [/blocks/workspace-settings](/blocks/workspace-settings) | `workspace-settings` |

The full lists are the [component index](/components) and the [block index](/blocks).
