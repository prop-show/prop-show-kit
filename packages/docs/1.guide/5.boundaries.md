# Boundaries with shadcn-vue

> shadcn-vue is the UI kit. PropShow Kit is an add-on registry beside it. The two are meant to be installed into the same project.

## What stays with shadcn-vue

These stay on the official path, even in a project that uses every PropShow entry:

- **Project setup.** Tailwind CSS, `components.json`, and the `cn` helper at `@/lib/utils` come from [the shadcn-vue installation](https://www.shadcn-vue.com/docs/installation.html). PropShow Kit assumes that setup is already done. The [Quick Start](/guide) lists the checks.
- **The CLI.** You install both registries with `shadcn-vue`. There is no second CLI and no `npm install` for this kit.
- **Primitives.** `button`, `input`, `textarea`, `badge`, `tooltip`, `dropdown-menu`, `avatar`, `separator`, and the rest of the official set stay official. When a PropShow entry needs one, its registry JSON names that primitive and the CLI fetches it from shadcn-vue.
- **Tokens and theme.** Color, radius, and dark mode come from your shadcn-vue theme. PropShow components use those semantic tokens so light and dark mode keep working without a second theme file.

If the official registry adds a component you were missing, you can install that official component. Nothing in PropShow Kit disables or wraps the official set.

## What this registry adds

PropShow Kit publishes only the entries shadcn-vue does not ship as product UI:

- **Components** such as Frame, Layer Card, Layer Dialog, Inline Tip, Status Badge, Copy, Filters, Slider, Delete Resource, Sortable List, and the pricing family. They are the gaps: things product screens keep needing, with props and slots documented on each page.
- **Blocks** such as the workspace screens (工作台). They are ready sections built from those components and from official primitives.

That split is the whole product. [Components and blocks](/guide/components-and-blocks) is the longer version, with the group list.

## What this registry does not do

- It does not replace shadcn-vue, and it does not fork it. A project without shadcn-vue cannot install these entries cleanly, because they import `@/lib/utils` and official primitives.
- It does not vendor copies of `button` or `dialog` under `@propshow`. If the install log mentions `button`, that file comes from the official registry.
- It does not ship as a versioned library. You will not find a changelog that bumps your `node_modules`. Re-running `shadcn-vue add` on an entry you already edited will offer to overwrite those files. Your edits live in git, not in an upstream release.
- It does not style a second, competing system. If a screen looks wrong next to an official component, the mismatch is usually a local edit or a missing official primitive, not a PropShow theme you forgot to turn on.

## A practical split

| Need                                                      | Install from                |
| --------------------------------------------------------- | --------------------------- |
| Button, input, dialog, dropdown, badge                    | shadcn-vue                  |
| Framed panel, pricing card, filter builder, sortable list | `@propshow` component       |
| Overview, team directory, settings form                   | `@propshow` workspace block |

Official primitives and PropShow entries are designed to sit in one tree. A workspace block imports Frame from this registry and Button from shadcn-vue in the same screen. That is the expected shape, not a layering mistake.
