# Contributing

PropShow Kit is an add-on registry for shadcn-vue. Source in `packages/ui` is what the CLI copies into other projects. The site in `packages/docs` is [kit.prop.show](https://kit.prop.show/).

Issues and pull requests are welcome. One focused change is easier to review than a mix of a new block, a docs rewrite, and a dependency bump.

## Report something

- Install failure, a broken preview, or a wrong docs page: [bug report](https://github.com/prop-show/prop-show-kit/issues/new?template=bug_report.yml).
- A component or block you want added: [component or block request](https://github.com/prop-show/prop-show-kit/issues/new?template=component_request.yml).
- A vulnerability: [SECURITY.md](SECURITY.md). Do not put exploit details in a public issue.
- What already shipped: [CHANGELOG.md](CHANGELOG.md) and the [blog](https://kit.prop.show/blog).

## Set up

Requirements: Node.js 22.18 or newer, and [Vite+](https://viteplus.dev/) (`vp`).

```sh
vp install
vp dev
```

`vp dev` builds the registry and starts the docs site. The usual local URL is `http://127.0.0.1:3000/`. Registry URL flags for another device are in the README under local debugging.

## Where to edit

| Path                            | What it is                                                                  |
| ------------------------------- | --------------------------------------------------------------------------- |
| `packages/ui/registry/`         | Component and block source. This is the code an install copies.             |
| `packages/ui/registry.json`     | Registry index: name, type, dependencies, files.                            |
| `packages/docs/.docs/public/r/` | Built registry JSON. Regenerated by `vp run ui#build`. Do not hand-edit it. |
| `packages/docs/`                | Docs pages. `1.guide`, `2.components`, `3.blog`, `4.blocks`.                |
| `artifacts/illustrations/`      | Empty-state SVGs. Workflow: `artifacts/illustrations/SKILL.md`.             |

A new registry item needs a docs page, a `registry.json` entry, a rebuilt `r/*.json`, and an illustration. `node artifacts/illustrations/check.mjs` fails when an item has no scene. Do not edit `artifacts/illustrations/svg/*.svg` by hand. The generator rewrites them.

Blocks ship with sample quotes, logos, links, and in-memory data. Docs should say what a user has to replace. The guide page on pitfalls lists the usual leftovers.

The docs landing (hero and feature list in `packages/docs/.config/docs.yaml`) is the public homepage. Leave it unchanged unless the pull request is specifically about that page.

## Checks

From the repository root:

```sh
vp check
vp run ui#test
vp test run --passWithNoTests
```

`vp check` formats, lints, and typechecks. `vp run ready` also builds the docs site. Run that when the change affects registry output, docs pages, or the site shell.

For illustration-only edits, also run:

```sh
node artifacts/illustrations/check.mjs
```

## Pull requests

- Describe what changed and how you verified it. The pull request template is the checklist.
- Commit generated registry JSON in the same change as the source that produced it.
- Keep attribution in `NOTICE` and `THIRD_PARTY.md` when a block is adapted from another project.
- Contributions are licensed under the [MIT License](LICENSE) that covers this repository.
